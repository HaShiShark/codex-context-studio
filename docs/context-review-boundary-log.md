# 上下文审查边界日志

本文档记录只在构建上下文审查功能时出现的实现事实、模糊边界和决策。产品契约位于 `docs/context-review-suggestions.md`；本日志说明不确定边界是如何解决的，并且每当实现暴露新边界时都必须更新。

## 2026-07-12：现有持久化

发现：`pending_context_review` 已序列化到代理 session 的 `session.json` 中，并在代理启动时加载。

决定：继续让代理 session 成为唯一的持久所有者。不新增第二个审查数据库，也不在 React/Web 状态中持久化待处理审查。进程运行期跟踪保留在内存中，而已完成的审查可以跨重启保留。

## 2026-07-12：什么操作会删除持久化审查

模糊点：打开旧对话与继续旧对话不是同一件事，而 Codex Desktop 没有向这个配套应用提供可靠的“标签页已打开”事件。

决定：只有同一 session ID 的常规主请求才具有权威性。该请求会在转发前清除待处理审查。仅在 ctx 中加载 session，或在 `.codex/sessions` 中检测到它，都不会清除任何内容。

## 2026-07-12：进程身份

模糊点：只检查进程名是否存在，无法识别应用重启，也可能混淆多个名称相同的辅助进程。

决定：检测 `Codex.exe` 和 `ChatGPT.exe`，然后使用最早匹配进程的可执行文件名、PID 和创建时间作为本次运行的锚点。锚点变化时，建立一套新的内存目标集合。待处理审查不受影响。

实现发现：当前打包的桌面应用会运行多个 `ChatGPT.exe` 进程和一个 `codex.exe` 资源进程。PowerShell 输出的 UTC 启动时间带七位小数，而 Python 的 ISO 解析器只接受六位。检测器现在会规范化精度，并把最早匹配的进程作为稳定运行锚点；之后创建的辅助进程不会重置各 session 的计时器。

## 2026-07-12：Session 存档检查

要求：空闲目标只有在其 ID 仍存在于 Codex session 存储中时才符合条件。

决定：复用仓库现有的 Codex session ID 扫描器，不在调度器中另造文件名解析。自动生成会检查活动的 `.codex/sessions`；有意排除 archived session，因为需求明确指定 `.codex/sessions` 作为活动存档检查位置。

## 2026-07-12：跨进程即时取消

发现：调度器/模型循环运行在 Web 后端，而常规请求从 FastAPI 代理进程进入。轮询无法实现即时取消。

决定：由代理负责取消。常规主请求开始时，在代理 session 上记录取消 generation/token。Web 模型循环在流式响应期间和各工具轮次之间，通过现有取消回调轮询该 token。Token 变化会中止 draft 并阻止存储。取消范围按 session ID 隔离。

## 2026-07-12：提案工具结构

要求：模型通常应一次分析并提交完整的选择性编辑，而不是进行许多小工具轮次。UI 审查摘要不需要很长，但压缩后的 transcript 节点可能需要很长。

决定：保持手动聊天页面的 `write_nodes` 不变。为 Suggestions 提案构建一套工具 schema，接收节点操作和 `review_rationale`。空闲自动化和 Suggestions 页面上的 `Analyze now` 操作都使用这套提案运行时。这样，模型第一次响应就能携带完整的 draft 编辑和面向用户的理由。底层写入实现仍然共用。

如果 provider 协议仍要求工具结果后的后续轮次，运行时不得要求模型重新设计编辑。运行时直接使用已提交的 `review_rationale`。

## 2026-07-12：设置语义

决定：在 Context Model 设置下新增持久化开关。启用时显示按分钟计量的 `Suggestion trigger interval` 数字字段，默认值为 10。关闭开关会取消正在运行的自动审查，但保留已完成的待处理审查，手动分析也仍然可用。

保存的设置是产品事实来源。环境变量继续作为开发和部署时的强制禁用/覆盖控制。

## 2026-07-12：验证发现

- 已确认打包的桌面应用实际使用多个 `ChatGPT.exe` 进程和一个 `codex.exe`；进程检测现在能够适配这套真实布局。
- 活跃 Codex session 扫描器找到了当前 `.codex/sessions` 目录树，并按设计从自动审查资格中排除 `archived_sessions`。
- UI 验证确认，只有启用自动建议时才显示间隔行，保存的默认值为 10 分钟。
- 现有 Vite 大 chunk 警告和 Starlette/httpx 弃用警告与此功能无关。

## 2026-07-12：多 Session 通知

发现：原始 Electron watcher 只检查 `active_session_id`。自动审查开始跟踪桌面进程本次运行中使用过的每个 session 后，这会隐藏非活跃目标 session 已完成的审查。

决定：检查每个代理 session 中新创建的待处理审查。Watcher 启动时，用 Electron 启动前已存在的审查填充 seen-ID 集合，防止重启后突发大量过期通知。之后创建的每条审查都可通知一次，点击通知会打开对应 session。

## 2026-07-12：审查文案必须使用提案语气

用户反馈暴露了语义错误：第一个自动工具字段名为 `review_summary`，这会诱导模型把 draft 操作描述成已经完成，并暴露节点/token 等实现细节。

决定：将提案专用字段干净迁移为 `review_rationale`。它面向审查者编写，必须解释提案原因、与当前任务的相关性、保留的信息和风险。必须使用“待处理/提案”语气，且不得暴露节点 ID、token 数量、工具名称或 draft 执行机制。

由第一版 schema 创建的持久化审查 draft 可能包含旧文案。新审查携带 `review_schema_version: 2`；代理重启时不恢复更早的临时 draft。这样可移除过时的实现导向文案，而不触碰规范 transcript。

## 2026-07-12：审查清除后的 UI

发现：全局的 `isMainChatBusy` 说明同时渲染在待处理卡片和空状态中。实时事件虽然正确删除了审查，但空页面随后会显示一条关于已不存在审查的警告。

决定：主聊天活动可以在审查仍存在时禁用不安全操作，但不会创建 Suggestions 页面状态消息。审查消失后立即渲染常规空状态。预览、应用和丢弃也不在状态转换后保留成功横幅；操作错误仍保持可见。

## 2026-07-12：Provider 下拉菜单圆角

发现：provider 菜单容器有圆角，但 `overflow-y: visible` 导致矩形的选项悬停背景越出圆角。

决定：使用 `overflow: hidden` 裁剪 provider 菜单内容。当前设置布局中的 provider 列表刻意不限制高度，因此菜单不需要内部滚动。
