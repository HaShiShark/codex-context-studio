# 附加工具的结构化展示

## 目标

在上下文地图中完整呈现 Codex Responses Lite 的 `additional_tools` provider item，同时避免让用户面对难以阅读的大段原始 JSON。

结构化视图只是一层展示投影。存储 transcript 和重建请求时，规范的 provider item 保持不变。

## 产品行为

### 折叠的上下文节点

常规上下文地图节点保持紧凑，并根据原始 provider item 显示其 token 权重。

### 展开的上下文节点

展开后的节点显示：

- Provider item 的类型和角色。
- 顶层条目数。
- 可直接调用的工具数量。命名空间只是结构容器，因此统计其子工具，而不统计命名空间本身。
- 在 `exec` 描述中明确声明的嵌套工具。
- 标记为“已列出工具”的总数，因为请求文本中可能没有延迟加载的运行时工具。
- 全部展开、全部折叠和查看原始结构的操作。

每个顶层工具都是一个可折叠区块。展开区块后，必须完整显示其全部 provider 内容，不得截断。

## 按类型展示

### 自定义工具

- 在区块标题中显示 `name` 和 `type`。
- 将完整 `description` 按 Markdown 渲染，并保留标题、列表、换行和代码围栏。
- 将 `format.type` 和 `format.syntax` 显示为元数据。
- 将 `format.definition` 显示为完整代码块。

### 函数工具

- 显示完整描述。
- 明确显示 `strict`。
- 将 JSON Schema 参数显示为递归字段行。
- 显示属性名、类型、是否必填、默认值、枚举值或常量值、描述、嵌套属性、数组元素 schema 以及 schema 约束。
- 显示 `additionalProperties` 和所有无法识别的 schema 键。

### 命名空间

- 显示完整的命名空间描述。
- 使用相同的按类型渲染器显示每个子工具。
- 递归支持嵌套命名空间。

### 未知字段

已知字段使用语义化布局。所有未知字段都通过通用的递归键值检查器显示，确保 Codex 协议未来新增字段时不会在 UI 中悄然消失。

## 完整性规则

1. 折叠只改变可见性，绝不从结构化模型中删除内容。
2. 描述、schema、语法定义、子工具和未知字段均不得截断。
3. 原始 JSON 继续作为审计视图提供，但不是默认阅读方式。
4. 前端绝不把展示投影写回 transcript。
5. Token 数量和上下文地图权重使用序列化后的原始 `additional_tools`，不使用标签、预览、展开状态或 Markdown 输出。

## 当前捕获到的结构

用于验证的 GPT-5.6 Lite 条目包含：

- 4 个顶层条目。
- 展开 collaboration 命名空间后，共有 9 个可直接调用的工具。
- `exec.description` 中明确声明了 16 个工具。
- 总计明确列出了 25 个可调用工具。
- 按项目当前 tokenizer 计算，原始 provider item 约为 5,737 个 token。

实际运行时的工具数量可能更多，因为 exec 契约明确允许省略延迟加载的嵌套工具，并通过 `ALL_TOOLS` 在运行时发现它们。

## 验证

- 纯契约测试覆盖数量统计、exec 嵌套工具提取、命名空间递归和原始 token 权重来源。
- 现有 provider item 保留断言保持不变。
- TypeScript 类型检查和 React 生产构建必须通过。
- 使用捕获到的 Lite transcript 对上下文地图进行视觉检查。

## 2026-07-13 验证结果

- 捕获到的四条目 Lite item 显示约 `5.7k` token，替代了错误的、基于摘要计算的 `0.1k` 权重。
- 展开后的标题显示 4 个顶层条目、9 个直接工具、16 个 exec 内工具和 25 个已列出工具。
- “全部展开”会打开 10 个结构区块：4 个顶层条目和 6 个 collaboration 子项。16 个 exec 声明仍完整呈现在 Markdown 描述中，没有被虚构成 provider item。
- 渲染后的 DOM 中包含完整 Markdown 描述、自定义语法定义、strict 标志、递归参数 schema、必填列表、命名空间子项和原始 JSON。
- 在常规上下文地图宽度下，组件宽度测得为 697px，没有可见的横向溢出。
- 在刻意缩窄到 184px 的组件宽度下，容器响应式操作、缩进和 schema 元数据同样没有产生可见的横向溢出。
