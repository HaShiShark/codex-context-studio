# 上下文地图 Exec 展示决策

## 2026-07-13：仅作为展示投影

决定：不把 exec 展开成新的 transcript item。外层 `custom_tool_call` 和 `custom_tool_call_output` 仍是仅有的规范 provider item。嵌套调用只存在于派生的前端展示模型中。

原因：修改 transcript 会破坏所要求的无损 `input -> transcript -> input` 契约，还可能创建 Responses 在线协议中从未存在的 call ID。

## 2026-07-13：只解析，绝不执行

决定：使用 ECMAScript 解析器解析 `exec.input`。不得通过 `eval`、`Function`、浏览器 realm 或 Code Mode 运行时执行源码。

原因：源码由模型生成，可能包含副作用。展示分析必须保持确定性和只读。

## 2026-07-13：精确计数必须有静态证据

决定：只有每个显示的调用都来自直接调用或可静态解析的数组映射时，才报告精确数量 `N`。动态控制流回退到外层 exec 卡片。

原因：循环中的调用表达式不能证明它恰好运行了一次。产品文案不能夸大 transcript 能够证明的事实。

## 2026-07-13：聚合输出不等于单命令输出

决定：当 exec 包含多个嵌套调用时，不把外层聚合输出附到每条命令上。单条记录显示中性提示。只有一个嵌套调用时，可以安全复用外层输出。

原因：Codex Desktop 有实时的嵌套执行事件，但当前经代理的 Responses transcript 只包含聚合的 exec 输出。

## 2026-07-13：语言区域 Bug 属于本次范围

决定：将 `uiLocale` 从上下文地图节点列表传入 `MessageContent`。

原因：如果不传，工具组会默认使用 `en-US`，导致其他部分都是中文的界面中出现 `Used 1 tool`。Exec 兼容性直接暴露了这个问题，并且已有明确的渲染路径。

## 2026-07-13：动态表达式不能伪装成确定结果

决定：对于条件表达式、逻辑短路表达式、循环、switch 和 try/catch 流程，除非能够静态确定所选分支，否则不分配精确数量。函数体在声明时忽略，只有通过受支持的静态 map 回调展开时才分析。

原因：在语法树中发现工具调用，并不能证明 JavaScript 执行了该分支或调用了该函数。第一次解析器检查在边界审查时暴露了这一点，因此在完成前收紧了行为。

## 2026-07-13：未完成的 Exec 调用保留外层卡片

决定：运行中或错误状态的 exec 不展开为“命令已完成”的展示。

原因：静态程序可能列出四个调用，但运行时在第一个之后就失败。如果没有嵌套运行时事件，transcript 无法证明完成数量。

## 2026-07-13：真实 Transcript 验证

当前 transcript 生成了具有精确静态计数的中文分组，包括 `已运行 3 条命令`和`已运行 4 条命令`。三命令分组展开为三个不同的预览，每一行都使用聚合输出提示。中文节点中不再存在英文工具组标签。
